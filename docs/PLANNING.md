# hongsihyeon.dev(가칭) 기획 문서

## 1. 프로젝트 개요

- **한 줄 정의**: 첫인상은 포트폴리오, 파고들면 블로그·SNS·방명록으로 이어지는 개인 웹 공간.
- **비유**: 미니홈피의 "일촌평/다이어리" 감성 + 개인 기술 블로그 + 트위터 같은 짧은 글 타래를 한 도메인 아래 묶은 형태.
- **운영 방식**: Blog/Notes 콘텐츠는 코드로 직접 작성(Git 커밋 = 콘텐츠 발행). 다만 SNS처럼 가볍게 글/상태를 올리고 싶다는 요구가 추가되면서 **로그인 기능 + DB(Neon)**가 도입됨 — 방명록 외에도 런타임 데이터가 생기는 구조로 변경.
- **현재 상태**: 홈페이지 + 로그인/회원가입 1차 구현 완료 (사이드바 로그인 상태, 관리자 전용 Online/Offline 상태 위젯, 비로그인 Contact 폼). Blog/Notes/Guestbook 라우트는 아직 미구현.

## 2. 목표

- 처음 오는 사람이 "이 사람 누구고 뭐 하는 사람인지"를 첫 화면에서 바로 파악할 수 있게 한다.
- 더 알고 싶은 사람은 메뉴를 통해 블로그(긴 글)·짧은 기록(SNS 느낌)·연락 수단으로 자연스럽게 이동한다.
- 방문자가 아주 가볍게 흔적을 남길 수 있게 한다(방명록).
- 콘텐츠 발행 과정이 "코드 커밋" 그 자체이도록 유지해 별도 CMS/관리자 페이지 운영 부담을 없앤다.

## 3. 정보 구조 (사이트맵)

```
/                → 홈 (포트폴리오)
/blog            → 블로그 목록 (긴 글, 태그/아카이브)
/blog/[slug]     → 블로그 글 상세
/notes           → 짧은 기록 목록 (트위터형 타임라인)
/notes/[id]      → (선택) 짧은 기록 개별 퍼머링크
/guestbook       → 방명록
/contact         → 연락 수단 (메일 폼 또는 mailto)
```

- 전역 네비게이션(헤더 or 사이드): Home / Blog / Notes / Guestbook / Contact.
- 홈은 "허브" 역할만 하고, 실제 깊은 콘텐츠는 각 하위 경로에 위치.

## 4. 페이지별 상세 기획

### 4.1 홈 (`/`) — 구현 완료
- **사이드바** (전역 레이아웃, 데스크톱은 고정 aside / 모바일은 Sheet): 로그인 상태 표시(비로그인 → 로그인/회원가입 링크, 로그인 → username + 로그아웃).
- **상태 위젯**: Online/Offline 배지 + 짧은 메시지(예: "업무시간 평일 09-17시"). 관리자만 수정 가능, 나머지는 읽기 전용.
- **Contact 폼**: 이름 / 답변받을 이메일 / 내용 3개 필드, 로그인 없이 누구나 제출 가능, nodemailer로 관리자 이메일에 발송.
- 포트폴리오 콘텐츠(자기소개, 프로젝트 카드 등)는 이번 단계에서 의도적으로 제외 — 추후 별도로 채울 예정.

### 4.2 Blog (`/blog`, `/blog/[slug]`)
- Velog류 기술 블로그 느낌: 제목, 날짜, 태그, 목차(선택), 본문.
- 목록 페이지: 태그 필터, 최신순 정렬.
- 콘텐츠는 MDX 파일로 저장(예: `content/blog/*.mdx`), 파일 자체가 곧 글.

### 4.3 Notes (`/notes`)
- 트위터/미니홈피 다이어리 같은 짧은 글. 타임라인 형태(최신이 위).
- 텍스트 위주 + 선택적으로 이미지 1장 첨부 가능.
- 블로그보다 훨씬 가벼운 포맷 — 짧은 생각, 근황, 링크 공유 등.
- 콘텐츠는 별도 짧은 MDX/JSON 파일 모음으로 관리(예: `content/notes/*.mdx`).

### 4.4 Guestbook (`/guestbook`)
- 로그인 없이 이름(닉네임, 자유 입력) + 메시지를 남기는 가벼운 방명록.
- 목록은 최신순, 페이지네이션 또는 무한 스크롤.
- **콘텐츠 관리 원칙과의 충돌 지점**: 이 기능만은 "방문자가 실시간으로 생성하는 데이터"라서 코드/Git 커밋 방식으로는 관리할 수 없음. 최소한의 서버 저장소가 필요한 유일한 예외 영역.
- 스팸/어뷰징 방지가 필요 (아래 5.3 참고).

### 4.5 Contact — 구현 완료 (별도 라우트 아님)
- 별도 페이지 대신 홈페이지 안의 섹션으로 구현. nodemailer + Gmail SMTP로 발송, 허니팟 필드로 최소 스팸 방지.

## 5. 기능 명세 및 기술 스택

### 5.1 공통 스택 (확정, 구현 완료)
- Next.js 16 (App Router) + React 19 + TypeScript + Tailwind CSS v4.
- **DB**: Neon Postgres (Vercel 통합) + Drizzle ORM (`drizzle-orm/neon-http`).
- **인증**: Auth.js(NextAuth) v5, Credentials + JWT 세션. 회원가입은 자체 구현(서버 액션), 관리자 승격은 `npm run promote-admin -- <email>` 스크립트로 수동 처리(회원가입 자체는 항상 일반 유저로 생성됨).
- **UI**: shadcn/ui (Base UI 기반, `base-nova` 스타일) + Pretendard 변수 폰트.
- **메일**: nodemailer + Gmail SMTP.
- **다크모드 미사용** — 단일 테마로 고정 (`.dark` 클래스가 적용될 일이 없도록 구성).

> ⚠️ 이 저장소의 `AGENTS.md`는 "설치된 Next.js가 알려진 버전과 다르다"고 경고했고, 실제로 확인해보니 Next.js 16에서 **Middleware가 Proxy로 이름이 바뀜**(`proxy.ts`, 동작은 동일). 이번 스코프엔 라우트 보호가 필요 없어 아직 사용 안 함. 또한 shadcn/ui도 예상보다 크게 달라져 있었음 — Radix 대신 `@base-ui/react` 기반, 컴포넌트가 공용 `shadcn` 런타임 패키지에 의존하는 새로운 `base-nova` 스타일 체계로 바뀜. 컴포넌트를 다룰 땐 기억에 의존하지 말고 실제로 생성된 `src/components/ui/*` 코드를 확인해서 API(`render` prop 등)를 맞춰야 함.

### 5.2 콘텐츠 관리 (Blog / Notes)
- 방식: **코드로 직접 작성** — MDX 파일을 레포에 커밋하는 방식으로 확정.
- 예시 구조:
  ```
  content/
    blog/
      2026-01-15-my-first-post.mdx
    notes/
      2026-02-03-short-thought.mdx
  ```
- 각 MDX 프론트매터에 title, date, tags(블로그), 선택적 image 등을 정의.
- 빌드/요청 시 파일 시스템을 읽어 목록·상세를 렌더링(별도 DB 불필요).

### 5.3 Guestbook 데이터 저장 (재검토 필요 — 상황 변화)
- 로그인 기능 때문에 이미 Neon DB가 도입되어 있으므로, 예전에 고민하던 "옵션 A(서버리스 DB) vs 옵션 B(모더레이션 큐)" 중 A가 추가 인프라 비용 없이 자연스러운 기본 선택지가 됨.
- 다만 Guestbook 자체는 아직 미구현 — 실제 구현 시 스팸 방지(허니팟 + 레이트리밋)를 다시 설계해야 함.

### 5.4 배포 — 확정
- Vercel + Neon Postgres(Vercel Storage 연동)로 확정.

## 6. 디자인 방향 (확정)

- **컬러**: 블랙&화이트 베이스 + 포인트 컬러 보라 (`--primary`, `--ring`을 보라 계열 oklch로 지정).
- **보더 없음**: Input/Textarea/Select/Button 등 shadcn 컴포넌트에서 정적 보더를 제거하고 `bg-muted` 채움으로 대체. 포커스 시 ring으로만 피드백.
- **각진 느낌**: `--radius`를 `0.25rem`(sm 수준)으로 축소.
- **단일 테마**: 다크모드 미사용 — `.dark` 클래스를 어디에도 적용하지 않아 시스템 다크모드 설정과 무관하게 항상 라이트 테마.
- **폰트**: Pretendard 변수 폰트 (`next/font/local`).
- 미니멀하고 타이포그래피 중심의 개인 사이트 톤은 유지 — 화려한 장식보다는 여백과 가독성 우선.

## 7. 단계별 로드맵

1. ~~**Phase 0 — 뼈대**~~ → **완료**: 홈페이지(사이드바 + 상태 위젯 + Contact 폼), 로그인/회원가입, DB/Auth 인프라 구축.
2. **Phase 1 — Blog**: MDX 기반 블로그 목록/상세 구현.
3. **Phase 2 — Notes**: 짧은 글 타임라인 구현 (Blog와 동일한 콘텐츠 관리 패턴 재사용).
4. **Phase 3 — Guestbook**: Neon DB 기반으로 구현 + 스팸 방지.
5. **Phase 4 — 포트폴리오 콘텐츠 & 다듬기**: 홈에 자기소개/프로젝트 카드 추가, SEO 메타데이터, OG 이미지, 접근성 점검.
